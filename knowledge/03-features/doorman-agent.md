# 司阍门口 Agent

## 背景与目标

司阍是面向家庭门口的低权限 OpenClaw 子 Agent。它和门外访客对话，处理快递、外卖、物业、维修、熟人访客、陌生访客、误按门铃和留言等场景。

它存在的核心原因是把“屋内主人和家庭系统的对话”与“门外访客和门锁对讲的对话”隔离开：

- **主 Agent** 面向主人，拥有家庭任务编排、设备控制、通知、自动化等高权限能力。
- **司阍 Agent** 面向门外人员，只做门口接待，只使用主人同步过来的低敏门房信息。
- **Miloco** 负责门锁事件、双向语音、会话状态、主 Agent 同步、手机 push 等可靠执行。

司阍不是另一个完整家庭助手，而是一个“门口值守人”。它应尽量像真实、稳重、礼貌的门房，但不能因为对话自然就扩大权限。

## 产品面

### 核心体验

用户侧体验是双通道：

```text
主人
  ↔ 主 Agent
      ↘ 同步门房任务 / 接收门口汇报
        Miloco
      ↗ 门铃事件 / 访客语音 / 门锁播报
门外访客
  ↔ 司阍 Agent
```

主人通常只和主 Agent 说话，例如：

> 今天有个退货件要上门取，顺丰，取件码 123456。

主 Agent 将这类任务同步到司阍可读的门房任务库。等快递员到门口时，司阍只在确认对方是来处理匹配快递事项后，才把允许对外说明的信息转达出去。

门外访客只和司阍说话，例如：

> 我是顺丰，来取退货件。

司阍根据当前 active 门房任务回复：

> 您好，取件码是 123456，快递在门口地垫旁，麻烦您取走，谢谢。

### 能做什么

- **门铃首问**：门铃按下后先问“你好，你是谁？有什么事情吗？”
- **快递派送**：默认请快递员把包裹放在门口地垫上，并提醒放稳。
- **快递取件/寄件**：只在匹配 active 任务且确认对方是快递员后，转达主人同步的取件码或寄件码。
- **外卖派送**：默认请外卖员把外卖挂在门把手上。
- **异常升级**：签收、到付、贵重件、外卖异常、维修/物业留言等需要主人处理的事项，会同步主 Agent，并通过 Miloco 推送手机通知。
- **通用留言**：物业、维修、熟人、陌生访客说明身份和来意后，司阍整理为门口留言。
- **误按结束**：误按、走错、找错门时礼貌结束，不打扰主人。
- **自然短对话**：可以对普通闲聊、玩笑、吐槽做一句自然回应；连续 3 次无关闲聊后礼貌结束。

### 不能做什么

司阍不能：

- 开门、解锁、上锁。
- 控制灯光、音箱、摄像头、窗帘、空调等室内设备。
- 查询主人是否在家、主人位置、家庭成员状态或室内情况。
- 透露门锁密码、门禁码、联系方式、安防状态、设备布局。
- 切换到主 Agent、模拟主人、继承主 Agent 权限。
- 向未确认身份和事项的人透露取件码、寄件码或其他临时任务信息。

### 场景流程

#### 快递派送

普通派送：

```text
访客：我是快递员，送快递。
司阍：您好，快递请放在门口地垫上，麻烦放稳，谢谢。
```

异常派送：

```text
访客：这个快递要到付，需要当面签收。
司阍：您好，我不能代签或开门。请说明快递公司、单号和需要处理的事项，我会记录给主人。
Miloco：同步主 Agent + 手机 push。
```

#### 快递取件 / 寄件 / 退货取件

```text
主人 → 主 Agent：今天顺丰来取退货件，取件码 123456。
主 Agent → 司阍任务库：写入 active 门房任务。
访客：我是顺丰，来取退货件。
司阍：您好，取件码是 123456，麻烦您取走，谢谢。
```

如果没有匹配任务：

```text
访客：我是快递员，来取件。
司阍：您好，我这里没有可转达的取件信息。请您稍等或留下快递信息，我会给主人留言。
```

注意：取件码/寄件码是主人给快递员的，不应向快递员索要。

#### 外卖派送

普通派送：

```text
访客：我是外卖员。
司阍：您好，外卖请挂在门把手上，谢谢。
```

异常派送：

```text
访客：外卖出问题了，汤洒了。
司阍：您好，外卖异常，请您先稍等一下，我马上给主人留言确认。
Miloco：同步主 Agent + 手机 push；后续可由主 Agent 使用现有能力给屋内音箱播报。
```

外卖异常不需要向外卖员道歉，不追问冗长订单细节。语音交互中只需让对方稍等，并把事件同步给主人。

#### 物业、维修、熟人、陌生访客

这些场景统一抽象为“门口留言”：

```text
访客：我是物业，通知明天楼道检修。
司阍：好的，我会给主人留言。
Miloco：生成 [司阍门口留言]，同步主 Agent，并发送手机 push。
```

如果来意不清楚，司阍先确认身份和事项；如果涉及开门、室内状态或住户隐私，先拒绝再引导留言。

#### 误按门铃

```text
访客：不好意思，我按错了。
司阍：没关系，再见。
Miloco：可生成普通门口汇报，但不发送留言 push。
```

## 研发面

### 端到端链路

```text
MIoT 门铃事件
  → backend/miloco/src/miloco/miot/client.py
  → DoorbellConversationService.start()
  → OpenClaw webhook / agent:doorman:doorbell
  → 司阍生成门锁播报文本
  → OpenClaw 插件执行 TTS / audio_sender
  → 门锁播放完成 callback
  → Miloco 开启访客拾音窗口
  → perception speech candidates
  → DoorbellConversationService.accept_speech()
  → 同一个司阍 session 继续下一轮
  → 超时 / 最大轮次 / 结束话术
  → 同步主 Agent / 手机 push / reset 司阍 session
```

核心实现文件：

- `backend/miloco/src/miloco/doorbell/conversation.py`：门铃会话状态机、OpenClaw 调用、拾音窗口、主人摘要、push、session reset。
- `backend/miloco/src/miloco/perception/client.py`：将门铃来源语音转写候选送入当前门铃会话。
- `backend/miloco/src/miloco/perception/collect/camera_adapter.py`：门铃调试音频保存。
- `backend/miloco/src/miloco/config/doorlock.yaml`：门铃、门锁音频、主人摘要、调试音频配置模板。
- `plugins/openclaw/src/actions/doorbell-reply-audio.ts`：OpenClaw 侧门锁播报 action。

### 会话隔离

门铃使用固定 session key：

```text
agent:doorman:doorbell
```

主 Agent 和司阍不共享普通对话上下文。门铃会话结束后，Miloco 会 reset 该 session，避免上一轮访客对话污染下一轮，例如上一轮误按或闲聊导致下一次门铃直接说“再见”。

这样会清掉右侧 Dashboard 的门铃历史，但当前是更稳的方案：牺牲一点历史展示，换取门铃会话干净可控。

### 职责边界

Miloco 后端不应把司阍做成“关键词流程机”。当前原则是：

- **模型理解语义**：访客类型、来意、外卖是否异常、是否需要给主人留言、是否是闲聊。
- **后端保证执行**：门铃状态机、session reset、手机 push、同步主 Agent、取件码匹配、安全边界。
- **强规则只保底**：权限、安全、取件码、签收/到付/贵重件、误按门铃等不可违背的行为。

这也是 `1ec3273 refine doorman owner message signaling` 的核心变化：减少后端对外卖异常和访客留言的关键词枚举，改为监听司阍回复中的稳定动作信号。

### 模型动作信号

Miloco 通过司阍回复里的稳定短语判断是否需要可靠执行后续动作。当前主要信号包括：

- `给主人留言`
- `给主人确认`
- `联系主人`
- `通知主人`
- `转达给主人`
- `稍等主人消息`
- `马上给主人留言确认`
- `外卖异常`
- `门口外卖出现异常`
- `外卖出现异常`

这些信号不是对访客解释系统能力，而是让自然语言回复同时具备“可被系统稳定识别”的特征。

### 主人摘要与手机推送

当会话结束、播放失败、达到最大轮次或出现需要主人处理的动作信号时，Miloco 会构造主人侧摘要：

```text
[司阍门口留言]
时间：YYYY-MM-DD HH:mm:ss
类型：门口访客留言
访客：...
司阍：...
状态：...
需要主人处理：是
建议主Agent处理：门口留言
```

普通无须处理的事件使用：

```text
[司阍门口汇报]
```

如果开启 `doorbell_owner_summary_phone_push_enabled`，同一事件会通过 Miloco 现有通知能力给用户手机发送简短 push。push 不取代主 Agent 摘要；两者是并行通知。

### 取件码安全

取件码/寄件码只能来自主人通过主 Agent 同步的 active 门房任务。司阍不得凭历史记忆、过期任务或猜测报码。

报码需要同时满足：

- 当前任务 `status=active`。
- 未超过 `expires_at`。
- 访客来意与任务匹配。
- 已确认对方是快递员或对应承运方。
- 任务内容明确允许对外转达取件码/寄件码。

如果条件不足，司阍应让对方稍等或留言，不应向快递员索要取件码。

### 自然对话和轮次控制

司阍需要像真人门房一样简短回应，但门铃不是闲聊入口。Prompt 侧约束为：

- 普通闲聊、玩笑、吐槽可以一句话自然回应。
- 不重复机械追问“请问您是哪位，来访有什么事”。
- 连续 3 次没有真实来意时礼貌结束。
- 单次门铃会话最多接收 `doorbell_max_turns` 次访客语音。

后端最大轮次是硬上限，Prompt 的 3 次闲聊策略是体验层约束。两者配合避免门口对话无限延长。
